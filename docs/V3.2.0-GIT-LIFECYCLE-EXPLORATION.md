**Date**: December 3, 2024
**Status**: Exploration Complete → Ready for Implementation

## Executive Summary

This document captures the complete exploration of integrating Git lifecycle events with GitVan's knowledge hooks system for v3.2.0.

**Vision**: Transform git from "commands" into a semantic graph where every operation is an RDF triple, and knowledge hooks react intelligently to patterns.

**Scope**: Design, architecture, and implementation roadmap for git lifecycle knowledge hooks.

## What Was Explored

### 1. Current Architecture Analysis ✅

**Finding**: GitVan already has:
- ✅ 4 core hook components (Registry, Orchestrator, Parser, Evaluator)
- ✅ 8 predicate types supporting SPARQL queries
- ✅ 5 git signals currently captured (pre-commit, post-commit, pre-push, post-merge, post-checkout)
- ✅ RDF-first storage with KnowledgeSubstrateCore
- ✅ Git-native state management

**Limitation**: Only 5 of 18 git hooks are captured; no semantic modeling of git events themselves.

### 2. Git Lifecycle Events ✅

**Discovered**: 10 primary git lifecycle events that can be captured:

| Event | Trigger | Available Data |
|-------|---------|-----------------|
| pre-commit | Before commit | Staged files, author, message preview |
| post-commit | After commit | Hash, parent, author, timestamp, files |
| prepare-commit-msg | Message default | Message type, branch, staged files |
| commit-msg | After message edit | Full message, author, branch |
| pre-push | Before push | Remote, commits, branches, force flag |
| post-push | After push | Remote, pushed refs, branch, timestamp |
| pre-merge | Before merge | Source, target, conflicts, commits |
| post-merge | After merge | Merge commit, parents, conflicts, files |
| post-checkout | After checkout | Previous branch, new branch, commit |
| post-rewrite | After rebase/amend | Old commits, new commits, head |

### 3. RDF Data Model ✅

**Designed**: Complete RDF ontology for git events:

```turtle
@prefix git: <http://example.org/git#> .
@prefix prov: <http://www.w3.org/ns/prov#> .

git:CommitEvent a rdfs:Class ;
  git:hash xsd:string ;
  git:author git:Author ;
  git:message xsd:string ;
  git:timestamp xsd:dateTime ;
  git:branch xsd:string ;
  git:filesAdded rdf:Seq ;
  git:filesModified rdf:Seq ;
  git:filesDeleted rdf:Seq ;
  git:parents git:Commit ;
  prov:wasAttributedTo git:Author .

git:Author a rdfs:Class ;
  git:name xsd:string ;
  git:email xsd:string ;
  git:commitCount xsd:integer ;
  git:seniority git:SeniorityLevel ;
  git:joinDate xsd:date ;
  git:lastCommit xsd:dateTime .
```

### 5. SPARQL Query Patterns ✅

**Designed**: Sophisticated queries showing git analytics:

```sparql
# High-risk commits (> 1000 lines)
SELECT ?commit ?author ?files WHERE {
  ?commit a git:CommitEvent ;
    git:filesChanged ?files ;
    git:branch "main" .
  FILTER(?files > 1000)
}

# Merge velocity by author
SELECT ?author (COUNT(?merge) AS ?count) WHERE {
  ?merge a git:MergeEvent ;
    git:author ?author .
}
GROUP BY ?author
ORDER BY DESC(?count)

# CI/CD failures before merge
SELECT ?merge ?branch ?failedTests WHERE {
  ?merge a git:MergeEvent ;
    git:source ?branch .
  ?branch ci:hasCI ?ciRun .
  ?ciRun ci:status ci:Failed ;
    ci:failedTests ?failedTests .
  FILTER(?failedTests > 0)
}
```

### 6. Implementation Architecture ✅

**Designed**: Complete three-layer architecture:

**Layer 1: Semantic Git Events**
- `GitEventCapture.mjs` - Hook into git operations
- 10 git hooks capturing semantic events
- Events stored as RDF triples

**Layer 2: Knowledge Hooks React**
- `GitLifecycleHooks.mjs` - Match patterns against git events
- SPARQL queries finding matching events
- Workflow execution from hook matches

**Layer 3: Reactive Workflows**
- Workflows receive git event context
- Actions: notify, create issue, update RDF, execute workflow
- Full automation pipeline

## Key Discoveries

### 1. Semantic Git Graph Enables Powerful Queries

**Before** (v3.1.0):
```bash
# "Which commits are large?"
# Answer: Manual script parsing git log
```

**After** (v3.2.0):
```sparql
# "Which commits are large?"
SELECT ?commit ?author ?size WHERE {
  ?commit a git:CommitEvent ;
    git:branch ?branch ;
    git:linesAdded ?size .
  FILTER(?size > 1000)
}
# Instant answer, cacheable, composable
```

### 2. RDF Enables Multi-Event Correlation

```sparql
# Find commits by junior devs with no reviews that broke tests
SELECT ?commit ?author WHERE {
  ?commit a git:CommitEvent ;
    git:author ?author ;
    git:branch "main" .

  ?author git:seniority git:Junior .

  OPTIONAL { ?review review:approvesCommit ?commit }
  FILTER(!BOUND(?review))

  ?commit git:triggeredBuild ?build .
  ?build ci:status ci:Failed .
}
```

### 3. Knowledge Hooks Enable Reactive Automation

```turtle
# "When this pattern matches, execute this workflow"
gh:DeployWhenReadyHook a gh:Hook ;
  gh:query "SELECT ?tag WHERE { ?tag a git:TagEvent ; ... }" ;
  gh:onMatch [
    op:execute op:DeployProduction ;
    op:withContext ?tag
  ] .

# No polling, no cron jobs, purely reactive
```

### 4. Author Entities Enable Context-Aware Automation

```sparql
# Different rules for different developer levels
SELECT ?commit ?review WHERE {
  ?commit a git:CommitEvent ;
    git:author ?author .

  ?author git:seniority ?level .

  # Junior devs: require 2 approvals
  # Senior devs: require 1 approval
  BIND(IF(?level = git:Junior, 2, 1) AS ?required)
}
```

## Architecture Decisions

### ✅ Decisions Made

1. **Model git as RDF triples** - enables queryability and composition
2. **Synchronous hook evaluation** - immediate response (block if needed)
3. **Author entities in RDF** - enable author-based queries
4. **Event retention policy** - 90 days detail, 1 year aggregates
5. **Hook definitions in TTL** - versioned, queryable, consistent

### 📌 To Be Decided

1. **Async vs sync event processing** - Hybrid in v3.3.0?
2. **Server-side hooks** - pre-receive, update hooks?
3. **Multi-repo correlation** - queries across repos?
4. **ML-based anomaly detection** - unusual patterns?
